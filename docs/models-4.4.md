Размеры в интерфейсе показаны в десятичных МБ/ГБ, как подписи файлов. Проверка свободного диска включает запас 25% и корректно обрабатывает нулевое свободное место. Это проверка диска, не свободной оперативной памяти. 3B требует больше RAM для весов, KV-кеша и runtime. Не заявляется гарантированная совместимость по одной только модели iPhone.

Новая установка запускается вручную в каталоге. Ранее начатая загрузка с сохранённым resumeData может возобновиться при возвращении в раздел ИИ. Новые модели показаны первыми; старые Qwen доступны отдельным раскрытием. Установленная или активная старая модель отображается без раскрытия. Смена оформления не сбрасывает раскрытый список. Результат скачивания выбирает активный ID, открытие чата остаётся отдельным действием.

## Совместимость с прежними данными

ID `light`, `standard`, `advanced`, файлы `Qwen2.5-*-Instruct-Q4_K_M.gguf` и ссылки старых сессий сохранены. Они не переименованы в Llama/Gemma. Загрузки с сохранённым resumeData по-прежнему находятся по старому ID. Новые семейства имеют свои ID и пути; скачивание, очистка и удаление не затрагивают другую модель. Существующие файлы не удаляются автоматически.

Параметры небольшого контекста теперь выбираются по `tier`, а не только по старому ID `light`. Экономный режим продолжает ограничивать контекст до 2048 токенов. Одновременно работает один native ресурс через прежний менеджер. Веса моделей не включаются в JS/IPA, меняется только каталог и настройки вызовов.

## Формат сообщений

`modelCompletionOptions` вызывается внутри `completeWithGuard` после ограничения контекста — для обычного ответа, редактуры, JSON-разбора и голосового режима. Параметр `jinja: true` включает шаблон из GGUF; если движок не поддерживает Jinja конкретного файла, установленный адаптер использует свой native fallback. Поддержка архитектуры Gemma 3 и шаблонов Gemma/Llama найдена в исходниках уже установленного `@pocketpalai/llama.rn@0.8.1-0`; зависимость не обновлялась.

Gemma не получает отдельную роль system: содержимое инструкций переносится в первое user-сообщение. Соседние сообщения одной роли объединяются, чтобы после неудачного/повторного запроса не нарушать чередование user/model. Исходные сообщения и сохранённая история не изменяются. Llama/Qwen сохраняют системную роль. JSON schema и другие параметры completion сохраняются.

Маркеры остановки:

- Llama: `<|eot_id|>`, `<|end_of_text|>`, `<|eom_id|>`.
- Gemma: `<end_of_turn>`, `<eos>`.
- Qwen: `<|im_end|>`, `<|endoftext|>`, `</s>`.

Проверки английского языка, коротких повторов, одной попытки переформулировки и отмены из 4.3 остаются общими для всех моделей. Модель не дообучалась. Названия режимов не доказывают, что Gemma 1B отвечает лучше Llama 1B или что 3B всегда быстрее/правильнее. Особенно важно отдельно проверить русские переводы и объяснения.

## Проверка файлов и источников

У новых моделей размер должен в точности совпадать с закреплённым файлом, затем проверяется заголовок GGUF. Недостающий байт, лишние байты, HTML вместо весов и HTTP-ошибка не приводят к выбору такой модели. Проверка не читает гигабайтный файл в JS. Записанный SHA-256 взят из метаданных источника: криптографическая проверка полного скачанного файла не реализована и не заявляется. Для старых Qwen сохранён прежний допуск размера ради совместимости.
